# 自由工程画板

## 核心

工程通过自然语言和数学关系成为可画、可读、可修改的对象。图形由表达需要决定，每个部位都可以向下关联程序实现。人的修改必须完整传递给实现层；源码与验证结果也要能反向解释到对应部位。

不要先套身体、器官或固定流程图。允许用文字、公式、自由笔迹、多边形、形状、分区与箭头组成任意二维画面。布局是作者的表达，不自动代表模块层级、时间、依赖或真实调用关系。

## 两种阅读深度

- 人读：图形上的说明只用自然语言和数学语言。写清目的、行为、条件、边界，数学变量说明含义和单位。不要出现源码路径、程序调用或执行命令。
- 机读：选中同一图元后，在 `implementation` 写语言、程序表达和实现说明，在 `anchors` 关联实际文件、符号、用途和依据。可用 `targets` 关联已有器官或数据流，但不是必填。
- 不凭空生成映射。读过实际源码再关联；没实现、没找到或尚不明确的部分，机读说明明确缺口。
- 公式可表示函数、集合、量词与约束，不因它含括号就改成程序描述。语法检查只能找线索，作者仍须复核人读文字。

## 创建与编辑

1. 先定位真实工程根目录，读取相关源码和测试；已有画板先用当前页面的本地 URL 或工程 `dir` 调用 `anatomy_selected_version`，以页面选定版本为准。仅未采用项目保存的旧画板使用 `anatomy_pending_edits`。
2. 新画板用 `anatomy_init({ repo, body, title, oneline })`。不传系统即从空画板起步，数据住在工程自己的 `anatomy-<slug>/`。
3. 用 `anatomy_board({ body })` 读取完整画板。构造或修改 `board.elements`，再用 `anatomy_board({ body, board })` 保存整张画板。保留稳定标识、其他图元、扩展字段和源码指纹。
4. 用 `anatomy_check` 查看结构、人读语言和源码证据。修正错误后 `anatomy_render` 输出二维画板，默认自动启动或复用本地识别服务并请求浏览器打开。使用返回的 `url` 实际检查文字与交互；只需文件时传 `serve: false`，不弹浏览器时传 `open: false`。
5. 用 `anatomy_map` / `anatomy_digest` 同步人读与机读摘要。点击部位的程序映射亦可用 `anatomy_board({ body, element })` 读取。

数据格式、画板操作和完整例子见 [README](../../README.md) 与 [可运行示例](../../examples/board-demo.mjs)。

页面通过选中部位附近的操作栏编辑，不使用常驻侧栏。双击文字或公式进入编辑；自然语言说明就地确认或取消，公式窗口保留追加、编辑指定条目和新建。程序表达与源码只放在明确打开的独立「程序映射」窗口，人读画面不展示这些内容。编辑确认前校验整张画板，通过后一次写入并进入一个撤销步骤；未确认草稿不是已保存意图。

## 已有工程的阅读引导

阅读已有工程时，先沿实际入口、主要数据处理、输出和关键分支核对源码，再组织图元。不要只交付一张节点目录或绘图操作示例。用 `board.reading = { summary, steps }` 保存工程导读；每个步骤用 `element` 指向已有图元，`title` 说明这一步要理解什么，`description` 用自然语言解释输入、处理、输出以及条件与边界。阅读顺序可以跨分支讲解，明确它与实际执行顺序的区别。让数学关系连接到对应处理，而非孤立堆公式。

对每条表达工程关系的箭头或直线填写 `text`：数据传递写具体内容，条件分支写触发条件，可替换实现写选择关系，数学关系写解释用途。不要用空名称或「连接」充数，不把算法选项画成依次执行的流水线。未知关系如实保留待说明；纯装饰线无需编造语义。既有场景可直接用作阅读路线，缺失主线时页面的部位索引只是兜底，不算完成工程导读。

工程导读在独立窗口选择路线，小阅读卡片提供上一步和下一步；程序映射按需另开。导读编辑须确认或取消：确认前检查整张画板，确认后一次写入；取消保留原导读，关闭窗口暂存草稿，再次打开可恢复。不要把草稿当成已确认意图。交付前实际走一遍：读者能说清工程目的、找到入口、沿命名关系追到结果，并在相同部位打开程序映射。确认后的导读和其他图元一起保存到选定版本。检查未纳入主线的分支和未命名关系，说明缺口。

## 图元约定

`body.board` 包含 `version: 1` 和 `elements`，顺序就是图层顺序。

- `id` 稳定且唯一，只用字母、数字、横线、下划线。
- `type` 可取 rect、ellipse、diamond、text、math、pen、polygon、line、arrow、frame。
- `x`、`y`、`width`、`height` 为有限数值，非连线图元宽高大于零。`rotation` 是角度。
- `text` 是自然语言；`math` 保留原有主数学表达。可选 `mathExpressions` 数组记录附加表达，每项含稳定 `id` 与数学内容 `value`；追加不得覆盖原表达，编辑只改目标条目并保留其笔迹与扩展字段。阅读、保存和核对意图时包含全部表达。`fill`、`stroke` 使用十六进制颜色，或 `none`；`fontSize`、`strokeWidth` 调整外观。
- `points` 是相对坐标对列表，按图元宽高缩放。笔迹至少两个点，多边形至少三个。
- 直线和箭头可用 `from` / `to` 绑定非连线图元；删除端点会在原位置保留并解除这一端的绑定。
- `implementation` 的 `language`、`code`、`note` 是机读文字，只记录，不自动执行。
- `anchors` 每项含文件相对路径 `file`，可含 `symbol`、`role`、`reason`、`sha256`。用途包括 implementation、interface、test、config、docs；别把测试伪装成实现。
- `targets` 每项为 `kind`（organ / flow）和 `id`。一个图元可关联多个工程对象，共享文件也允许关联多个图元。

纯装饰笔迹无需编造实现。若同一形状中某一区域需要独立机读，用可单独选择的多边形、形状或文字标出该区域，并为它写独立映射。

## 人的修改优先落地

「保存修改」直接写入工程画板目录的 `edits/versions/`，版本不可变；`edits/selected.json` 记录页面当前选定版本。用户无需下载、选路径或发送文件。页面历史选择是当前意图的唯一依据，不能依次应用所有历史版本。

- Codex 通过插件的标准 MCP 接口调用同名 `anatomy_*` 工具；无需 DSH 宿主。先定位当前工作工程下的 `anatomy-*/body.json`，多工程时按当前任务确认归属，给工具传 `dir`。不要把 MCP 进程启动目录当成用户工程，不自动选另一个工程的最新版本。
- 有对话中当前画板的本地 URL 时，开工先调用 `anatomy_selected_version({ url })` 自动识别服务对应的真实工程；没有网页上下文时才使用已定位的 `dir`。返回当前选择、完整画板、程序表达、源码锚点和 `selectionRevision`，不要求用户找文件。按这份意图分析改动，再用 `anatomy_selected_version({ dir, apply: true, selectionRevision })` 通过现有严格门禁落地上层意图；应用后重读源码并实施下层改动。
- 页面切换历史版本会明确建立相对于当前工程的恢复意图。AI 读取后若页面又切换、或工程版本变化，应用必须拒绝；重新读取并核对，不伪造哈希，不用 force 吞掉冲突。历史文件保留，不移走、不归档删除。
- 保存仅代表设计进入工程，不代表代码已实现。必须继续定位源码，实施用户要求、运行相关测试、复核映射与公式依据；没有证据不得声称严格对照已完成。普通图元的任意自然语言/公式不能被当前数值验证器自动证明。
- 只有未采用项目保存的旧画板才使用 `anatomy_pending_edits` 与下载包兼容入口。静态 HTML 必须由 `anatomy_render` 的项目服务打开才能写文件；断线时保留浏览器草稿、显示连接错误，不能冒充成功或退回强制下载。

自动排布按文字和数学内容撑开图形、避让节点和分区标题，保留关联与稳定标识。生成默认开启；自由绘画要保留作者位置可设置 `board.layout.mode = "manual"`。人工排布是表达，不能推断成实际执行顺序。交付要用真实视口查看导读、说明和程序面板；不要通过极小字号掩盖布局问题。

顶部「撤销」「重做」作用于已确认的画板修改，包括公式、程序映射、导读和排布；有编辑草稿时先确认或取消，再操作画板撤销。当前会话保留最近 60 步，刷新后不保证恢复。这与工程的不可变保存版本是两条记录：撤销不删除历史，AI 仍以页面选定的已保存版本为准；要传递撤销后的意图，需再保存并选定它。

## 源码和验证

`anatomy_mapping` 将图元的直接锚点纳入文件索引。`anatomy_impact` 的文件查询返回直接匹配图元；已有对象的影响路径是有依据的候选，不是自动得到的调用图。画板上的普通连线不自动产生工程依赖。

写入会记录新锚点的源码指纹。源码变化后，普通保存保留旧指纹并报告漂移。读过相关源码、意图和测试后，才能通过 `reviewSources: true` 更新已复核对象的基线。`anchor/not-checked` 说明源码根不明，应补根；文件存在、符号匹配都不等于实现正确。

自由图元当前不自动证明任意公式和自然语言，也不执行程序片段。已有结构模型的数值 `rules` 与 `anatomy_verify` 可继续使用；报告必须来自对应版本的真实测试，不得编造观测或篡改版本。其格式见 [可选结构模型参考](../../docs/structured-model.md)。未采用数值规则的画板，不为满足验证工具而强造器官与规则。

## 兼容已有工程

旧器官与流可自动生成自由图元并保留 `targets` 关联。已保存画板优先使用作者布局。只在工程本来采用该结构、或用户确实需要这种建模时继续维护器官、场景、数据流和架构规则；不要把兼容模型重新变成自由绘制的前置条件。

需要表示传递路程时使用数据传递耗时，方向按数据实际流动方向；区分估计、实测和未知，不以屏幕像素代替耗时。不做三维适配。

## 公式与手写

公式库包含代数、微积分、矩阵、概率、集合逻辑和工程关系。模板插入编辑框光标处；选中部位时默认追加数学表达，可明确编辑其中一条或新建独立公式，不默认为用户要替换旧公式。支持 LaTeX 数学记法；生成页面时本地排版为可阅读公式，不以原始控制序列代替人读表达。公式表示关系，不自动执行或证明。

手写识别同时提供「中文说明」和「数学公式」两种模式。它通过本机识别服务处理手写区域，也可识别选中的画笔图元。识别候选必须由读者校对并点击确认，才能新增图元或写入选中部位；数学结果区分追加、编辑选定条目和新建图元。每条表达可继续手写，分别保留中文说明与各条数学表达的笔迹，以及原程序映射。不得把识别结果默认为用户已认可的意图。

独立 HTML 支持离线公式排版；手写识别通过插件默认启动的本地服务提供，直接双击 HTML 不能自行启动 Python。检查渲染返回的 `service.status`，`starting` 只表示正在准备，`unavailable` 须说明具体原因，不能称为已就绪。服务安装、启动和首次模型加载见 [README](../../README.md)。模型没有加载或识别失败时说明实际状态，不假造候选内容，不把一般印刷文字识别测试说成完整手写质量验证。
