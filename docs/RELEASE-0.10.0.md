# Anatomy 0.10.0 更新说明

发布日期：2026-10-12。以下说明覆盖相较 `v0.9.0` 的更新。

Anatomy 现在以自由二维工程画板为主要界面。人在画板上用自然语言和数学表达设计意图，点击任意图元可以查看程序表达、源码关联与实现依据；AI 沿这些关联落实修改，并检查结构、源码证据和可验证的数学约束。

## 工程表达与阅读

- 支持矩形、椭圆、菱形、多边形、笔迹、直线、箭头、文字、公式和分区，以及移动、旋转、缩放、图层、多选、撤销和重做。
- 人读层保持自然语言与数学表达；程序片段和源码位置放在独立的程序映射中。图元可同时关联多个工程对象。
- 增加工程目的与逐步导读，可沿相连部位阅读并打开实现依据。没有阅读主线时显示部位索引，不猜测运行顺序。
- 箭头与直线展示关系名称，优先采用作者说明或已有工程数据流的名称；缺失时显示“关系待说明”。名称排版避让节点及其他标签。
- 支持源码反查、影响路径与已有业务场景。数据传递耗时和流向由工程数据或显式说明表达，未知值保持未知，不用画面距离代替实测耗时。

## 数学公式与手写识别

- 公式库提供 46 个可编辑模板，覆盖分式、根式、上下标、分段函数、方程组、微积分、矩阵、概率、集合逻辑及工程关系。
- 公式采用内嵌 KaTeX 的 MathML 输出，可离线预览，不执行表达式。
- 手写支持中文说明与数学公式，识别由本机 Python 服务完成。识别候选经过校对、确认后进入画板，原笔迹和程序映射保留，可撤销并继续编辑。
- 渲染时默认启动或复用本地服务；识别模型在后台准备，页面展示连接及加载状态。可选识别依赖缺失时仍可使用画板与项目保存。

## 项目保存、历史选择与 AI 实现

点击“保存修改”后，完整画板直接存入当前工程的专用目录：

```text
anatomy-<slug>/
├── body.json
├── anatomy.html
└── edits/
    ├── selected.json
    └── versions/
        └── v-<时间与标识>.json
```

- 每次保存生成不可变版本，保留图元、导读、程序映射、源码锚点、笔迹和扩展字段。
- 页面可命名保存、浏览历史并选定要应用的版本；有未保存修改时先保存，再切换历史。
- AI 通过 `anatomy_selected_version` 读取选定版本。当前画板 URL 可用于自动定位实际工程，无需用户下载、选择文件路径或发送修改包。
- 应用核对读取时的 `selectionRevision` 与工程基线。页面又切换版本或工程已变化时拒绝覆盖，不能用 `force` 跳过冲突。
- 选定版本入口固定执行严格校验，插件的宽松配置及额外参数不能放宽源码变化门禁；源码复核须显式确认。
- 选择旧版本会建立相对于当前工程的恢复意图，原历史文件保留。应用成功后记录消费状态，避免 AI 更新源码证据后重复应用旧快照。
- 项目保存依赖插件提供的本地服务。独立 HTML 或普通静态服务器无法直接写入工程，断线时页面保留草稿并报告连接问题。

## 布局改进

- 默认按文字和公式内容扩大图形，避让节点、旋转图形与分区标题，分区移动时携带内部图元。
- 修复嵌套分区避让父级标题和边距时，内部图元没有同步平移的问题。
- 页面可再次执行“自动排布”并撤销，图元标识、程序映射和连线关系保留。
- 可选择自由布局，保留作者的位置；窄窗口下工具栏和面板调整排版，减少内容遮挡。

## Codex 安装与调用

本版本提供 `.codex-plugin/plugin.json`、插件市场入口、作者技能与标准 stdio MCP，共 23 个工具。现有 DSH 接入仍可使用；Codex 接入无需 DSH 宿主或 OpenAI API 密钥。

克隆本仓库后，使用实际克隆目录安装：

```bash
codex plugin marketplace add /绝对路径/dsh-anatomy
codex plugin add anatomy@anatomy-local
```

重新加载插件或在新对话启用 Anatomy。也可以单独注册 MCP：

```bash
codex mcp add anatomy -- node /绝对路径/dsh-anatomy/scripts/mcp-server.mjs
```

在画板保存并选择版本后，对话中可直接说：

> 使用 Anatomy 插件，读取当前画板选定的保存版本，先对照工程源码检查差异，再按自然语言和数学约束实现，运行相关测试并复核映射。

只检查时可说：

> 用 Anatomy 读取选定版本，分析与现有工程的差异，暂时不修改代码。

保存不会自行触发 AI 改代码。在对话发起调用后，AI 读取选定意图，实施源码修改并提供验证依据。

## 升级与兼容

- Node.js 18 及以上用于插件、MCP 和项目保存；Python 用于本地 HTTP 服务。
- 需要中文或数学手写识别时，另行安装 `scripts/requirements-ocr.txt` 中的可选依赖；首次模型准备需要下载公开权重。
- 更新插件后重新生成画板，并打开工具返回的本地 URL。新版服务协议为 2，复用前检查项目版本能力，不把旧服务误认为可保存项目版本的服务。
- 既有结构模型、历史回退与旧修改包接口保留。采用项目保存后，以页面选定版本为准；旧下载包不能绕过当前选定意图。
- 工程数据应随工程备份或版本管理；`.anatomy-runtime/` 是本机运行信息，应保持忽略。

- `npm test`：129 项端到端检查、72 项 Node 测试、126 项兼容渲染检查，全部通过。
- `npm run test:ocr`：7 项 Python 服务测试，全部通过，覆盖识别分流、项目版本接口、冲突与本地访问边界。
- 已在已有工程画板验证保存、历史切换、选定版本读取与应用，以及窄窗口和桌面窗口排版。

结构、图元引用、源码指纹与数值证据可执行严格检查。任意自然语言或数学公式的完整语义仍需 AI 阅读和真实测试核对；保存意图不代表源码已经实现。手写识别是候选结果，复杂笔迹仍需校对。当前界面聚焦二维画板，三维代码仅保留兼容性。
