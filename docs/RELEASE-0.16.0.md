# Anatomy 0.16.0 更新说明

发布日期：2026-10-13。公式成为画板上的独立图形，可以局部擦除、补画和复制粘贴；文字层只编辑自然语言，AI 依据当前图形校对并严格落实工程意图。

## 文字与公式的实际编辑

双击自然语言说明、连线名称或图片图注，编辑框位于实际文字槽中，跟随原字号、对齐和旋转。其他图元持续可见，确认与取消保留现有草稿、撤销和项目保存机制。

公式库直接展示公式图形，选择后复制或放入画板。新公式使用随包内嵌的 MathJax SVG 3.2.2 排版，再生成独立 PNG，不再通过点击画板公式打开排版源码编辑框，也无需选择追加或覆盖旧表达。原始数学源码仍完整保存在机读来源中，旧数学数据继续兼容。

公式的局部擦除修改当前 PNG；画笔补画可成为公式图形的一部分。原始图、当前图和编辑来源一同保存，操作支持撤销与重做。普通文字按段擦除，普通导入图片不提供像素编辑。图元的移动、八方向缩放、旋转、顶点和端点编辑继续使用。

## 圈选识别与复制粘贴

套索支持拖动自由圈选和逐点点击后回车闭合。圈中笔迹、公式图形或补画内容后可识别中文或公式，按实际可见内容定位，只处理圈内部分；确认后在原位置生成自然语言或公式图形，圈外笔迹和图形像素继续保留。原稿与各来源的程序映射可追溯，不用识别后的结果代替原始笔迹。

选中图元使用 Ctrl+C／Ctrl+V 可在同一工程及加载基线内保留完整来源、程序映射与源码关联，Ctrl+D 可直接复制。公式库提供复制图形按钮，系统图片剪贴板取决于浏览器支持与权限，失败会报告实际状态。跨工程或不同基线的源码映射须先复核，可使用纯图片交换内容。

OCR 仍由本机服务运行，中文与数学候选都需要校对。无需识别也可保存画板笔迹；未识别内容不会被宣称为已理解的公式。

## AI 读取与严格校对

当前公式 PNG 通过标准 MCP `ImageContent` 返回，机读 JSON 保留原始数学表达、原图、当前图、笔迹、编辑记录与来源映射。文本中的图片数据使用简短说明；结构化结果仍保存完整数据用于严格应用。

初始公式标记为 `source-aligned`。擦除或补画后，`semanticStatus` 为 `needs-review`、`currentMath` 为 `null`；原公式只能用于追溯，不能冒充当前意图。这些草稿可保存、读取与普通渲染。

`anatomy_selected_version({ apply: true })` 和 `anatomy_render({ requireVerified: true })` 拒绝未经校对或校对过期的公式图形，force 无法绕过。AI 先读取当前 PNG，结合用户意图核对，再提交 `formulaReviews: [{ element, currentMath, visualHash }]`，并携带本次选择修订。图片 SHA-256 绑定本次校对；图片、选择修订或工程基线变化时拒绝继续。

校对工具另存不可变新版后严格应用，原版本保持不变。响应 `formulaReview` 指明来源版本与校对新版。校对仅确认当前上层语义，仍需实施实际源码、运行测试并复核证据，不自动证明业务实现。

## 保存、离线与兼容

画板仍直接保存在工程自己的 `edits/versions/`，页面可以选择历史，AI 自动读取所选版本。旧画板、图片、数学表达与工程历史继续兼容，不回滚用户业务数据。

当前 PNG 与公式原图使用同一图片预算：单图最多 6 MiB，相同内嵌数据去重后合计最多 8 MiB，项目保存请求最多 12 MiB。

生成的静态 HTML 内嵌常用公式的图形排版资源，绘图和公式编辑可离线运行。OCR 与写入工程保存文件仍需要本机项目服务；浏览器不能自行启动 Python。依赖缺失时保留草稿并显示实际状态，不承诺复杂笔迹的完美识别。

## 升级与验证

升级插件后重新开启会话或重启 Anatomy MCP 连接，再用 `anatomy_render` 重新生成页面，打开工具返回的本地服务地址。旧 MCP 进程继续持有启动时加载的代码，单独替换插件文件不会使其自动调用新版。工程数据与已保存历史保留。

- `npm test`：531 项 JavaScript 检查全部通过（129 项端到端、276 项 Node、126 项兼容渲染）；覆盖结构与源码门禁、公式图形及异步插入、局部编辑、套索、复制粘贴、原稿与映射保留、版本历史和图片指纹校对应用。
- `npm run test:ocr`：9 项 Python 检查全部通过；覆盖本地中文／公式识别服务、项目版本接口和访问边界；识别通路测试不能代替真实笔迹准确率评估。

实际浏览器验证了原位文字、PNG 局部擦除、补画、复制粘贴、圈选中文与简单公式、保存后 MCP 当前图片读取，以及未校对严格应用拒绝。复杂分式候选仍可能漏掉上下标或根号，需核对图形预览；不会自动替换原稿。

完整安装、数据格式与调用示例见 [README](../README.md)。
