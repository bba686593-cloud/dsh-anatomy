## 已有工程怎么读

通过「工程导读」先读工程目的并选择阅读路线。开始阅读后，小阅读卡片用「上一步／下一步」定位到具体部位；说明、图片、数学关系和命名连线在同一画板上阅读和修改。需要查看实现时明确打开「程序映射」。导读中的顺序是阅读安排，不会冒充运行时调用顺序。

由 AI 阅读真实源码后，在 `board.reading` 写 `summary` 与 `steps`。每步包含已有图元 `element`、自然语言 `title` 与 `description`。没有专门导读时优先使用工程已记录的业务场景；再没有时显示部位索引，并明确尚无阅读主线。导读中的人读说明沿用画板原位置编辑；确认前检查整张画板，通过后进入撤销与项目保存。无效步骤引用或程序语言进入导读会被拒绝。

箭头和直线的 `text` 是关系名称，说明具体传递什么、在什么条件下使用或依赖什么。空名称先取所关联工程数据流的名称，再缺失则显示「关系待说明」，不猜测关系。名称单独排版并避开节点及其他标签。导读聚焦某部位时只显示相连线的名称，可勾选「全部连线名称」展开全图。

## 怎么使用画板

从左侧选工具后拖动绘图；文字点击放置，多边形逐点点击，双击或回车结束。双击自然语言说明、连线名称或图片图注，在文字实际所在区域直接编辑；编辑框跟随文字的尺寸、对齐和旋转，其他部位持续可见。文字层只编辑自然语言，公式用画板图形操作。

左侧「画笔」或 P 留下原笔迹，直接进入画板、保存与历史，不必先识别。选中对象后，八个边角手柄调整大小，上方圆形手柄旋转；多边形的橙色顶点和连线的起终点可拖动。选择栏可改形、删除；「拆开框与内容」把框、文字和已有数学表达分开操作。

「橡皮」或 E 的大小滑条为 6–100 px。「局部擦除」可擦笔迹、文字、公式、普通图片、填充形状、框线和关系说明；「擦整个图元」移除命中的整个对象。非笔迹擦除保留原部位与源数据，擦痕随移动、旋转、缩放和复制；新的笔画按当前绘制顺序覆盖。公式可用画笔补充，补画与擦除均保留来源。擦除、补画和几何修改均可撤销、重做。

自然语言编辑时，点击其他部位会先校验整张画板，通过后提交当前修改；也可点击「✓」或按 Ctrl+Enter 完成，「×」或 Esc 取消。无效内容、正在输入的中文组合和未确认手写会保留草稿并阻止切换，显示实际原因。编辑中的「Σ 公式」先完成有效文字，再打开公式库；「手写」进入画板画笔。未确认草稿不会成为 AI 要实施的选定意图。

公式库只展示可选择、复制和放入画板的公式图形。点击画板公式不会打开排版源码输入；使用橡皮、画笔、套索和复制粘贴直接修改。原始数学源码在机读映射中保留，视觉修改后当前表达先标为待校对，避免 AI 仍照旧公式实施。

画面统一使用文档中的绘制顺序，关系说明跟随所属连线。识别结果与圈外残余保留原位置；补画不会跨过其他对象合进旧公式。图形外观、前后顺序和删除按需操作。选中图元后 Ctrl+C／Ctrl+V 复制粘贴，可保留同一工程及加载基线内的程序映射、源码关联与公式来源；Ctrl+D 可直接复制一份。跨工程或不同加载基线的完整图元粘贴会要求先核对映射，可改用纯图片。系统图片剪贴板取决于浏览器支持与权限，失败时页面会报告实际状态。

明确点击「程序映射」，才打开该部位的独立机读窗口，查看或编辑程序表达、实现说明与源码关联。代码与源码位置留在这个窗口，人读画板继续使用自然语言、数学和图片。

从一个图形拖箭头到另一个图形，可以建立随动连线。按 Shift 点击可多选；Alt＋点击循环选择重叠内容，擦孔可直接点到底下部位；空格拖动平移，滚轮缩放。二维常用快捷键：选择 V、画笔 P、套索 Q、橡皮 E、矩形 R、文字 T、公式工具 M；撤销 Ctrl+Z、重做 Ctrl+Shift+Z 或 Ctrl+Y、删除 Delete。公式和程序片段都不会自动执行。

顶部「撤销」「重做」有正在编辑的输入时先处理本次输入步骤，完成编辑后继续使用全画板历史。图片、笔迹、局部擦除、图形改形、说明、公式、程序映射、导读和自动排布共用画板记录；无效草稿须先修正或放弃。画板会话最多保留 60 步，含大图时受内存预算限制，刷新后不保证恢复撤销记录。撤销后做新修改会清空重做分支；这些操作不删除工程中已保存的历史版本。

「保存修改」先自动完成有效的原位编辑，再把已确认的画板意图直接写入当前工程的 `anatomy-<slug>/edits/versions/`，每次保存留下不可变的完整版本，`edits/selected.json` 记录页面选定版本。无效草稿先修正或取消，不会冒充保存成功。「历史版本」可以命名下一次保存、浏览和选择旧版；有未保存内容时先自动存成新版本再切换。AI 用 `anatomy_selected_version` 读取选定版本，不需要用户下载或传文件。应用前核对 `selectionRevision`、工程基线与源码哈希；另一页面切换或工程变化都会拒绝覆盖。保存意图不代表业务源码已实现，AI 仍需实施源码与验证。

浏览器草稿用于断线恢复。项目保存需要由插件的本地项目服务打开；普通静态服务器或独立 HTML 无法自行写入工程，页面明确报告未连接并保留草稿。「导出画板」仍可作为可选的文件交换功能。二维图形生成时可自动撑开内容并避让；已有高度、三轴姿态、空间笔迹或固定四角的工程默认保留几何，只有明确点击二维「自动排布」才重排；绘图、变形、插入和手写确认切入自由布局，保留作者位置，不自动重新排布。需要整理时明确点击「自动排布」，结果可以撤销；`board.layout.mode = "manual"` 表示自由布局。

## 三维视图

点击「三维视图」或底部「立体」进入同一画板的 GPU 场景，点击「回二维」返回。Three.js 运行时内嵌在生成的 HTML 中，不需要 CDN。浏览器及显卡驱动需要支持 WebGL2；无法创建或失去图形上下文时，页面报告原因并保留二维编辑入口。二维和三维共用 `board`、程序映射、撤销与项目版本，没有另一份三维工程文件。 文字与公式按原图元可用空间完整适配；关系说明朝向视角并避开节点和其他说明，过于拥挤时暂收起，选中后点「阅读大小」查看。聚焦和缩放会按实际显示大小调整文字清晰度。

进入后可用「选择」操作所有对象，包括形状、自由笔迹、连线、文字、图片和分区。点选后可直接拖动和旋转，Shift 点击增减多选，点击空白取消选择；在空白处拖动默认框选。姿态栏的「点选／框选／圈选」可切换选择方式，框选拖出矩形范围，圈选自由手绘范围，Shift 追加范围内的对象。框选／圈选后可直接用移动轴、旋转环或键盘操作；直接拖动对象前切回「点选」。选择的圈选只选已有对象，B「套索」另用于新建可拉伸轮廓。

选中对象显示红／绿／蓝移动轴，分别沿 X／Y／Z 移动；切换「旋转」可拖动对应三轴圆环，也可在 X°／Y°／Z° 输入角度。双击编辑内容，底部操作条提供「直接编辑」「程序映射」「删除」等操作。需要防止误移时点击位置开关锁定；锁定只限制位置与姿态，仍可选择和编辑内容。

四个固定、非共面的角点各用一束激光连接同一个笔尖，A／B／C／D 四条线长共同确定笔尖位置。这个笔尖是组件载体：选择侧栏形状、文字、公式，或导入、粘贴、拖入图片时，内容先附在笔尖上半透明预览。左键拖动搬动载体，移动轴限定方向；Alt 竖拖改世界高度，Alt+滚轮沿视线调前后。用旋转环、角度输入或键盘调整姿态，再按 Enter 或「放置」提交。移动预览不生成工程图元；四角不会跟随载体、相机或新增图元移动。

姿态工具栏旁将操作分成「对象／载体」与「视角」两组，窄屏也保留；展开「操作说明」查看选择、移动、旋转与相机控制。移动／旋转按钮、三轴环、X°／Y°／Z° 角度框及旋转键控制选中对象或笔尖载体；右键、中键与滚轮控制观察视角。

WASD 沿相机方位在地面移动，Q 降低、E 升高，Shift 三倍速。I／K 分别绕 X 轴正转／反转，J／U 分别绕 Y 轴正转／反转，Z／X 分别绕 Z 轴反转／正转；这些控制用于载体预览和当前选中的可移动组件。松开全部运动键提交一次已有组件变换；预览仍需 Enter 或「放置」才进入工程历史。Esc、窗口失焦或切工具取消在途操作，输入框、弹窗和中文组合输入期间暂停游戏按键。

自由笔迹工具可在任意位置按住左键起笔，不要求先抓笔尖。「落笔／抬笔」或笔工具下的 Enter 切换是否留墨，空格临时抬笔。笔迹保存真实逐点 `points3d` 与 `spatialInput.anchors`；提交笔迹或放置组件（包括图片、公式和套索实体）时，`board.spatialRig` 保存四角与笔尖，以后增加图元或重新打开画板使用同一组四角。「笔尖归位」只回到四角中央，单纯进入视图或搬动预览不会写入画板。

任意工具下，按住右键拖动旋转相机，按住中键或 Shift+右键拖动平移相机，滚轮缩放相机；方向键也只旋转相机。右键与中键控制观察视角，组件本身的旋转使用三轴环、角度框或上述旋转键。输入控件、展开的「更多」设置与可滚动面板内，滚轮按控件原有方式操作。「左键调视角」（H）提供左键旋转入口，俯视、斜视用按钮切换，Home 适配全图。相机动作只改变观察位置，窗口尺寸变化只调整视口，不会自动全图适配。

按住左键绘制时，同一鼠标再按住右键旋转或中键平移，相机移动期间笔尖与留墨暂停。松开右键／中键后，笔尖保持原来的空间位置，按新视角继续同一笔，不会跳笔；整笔仍只记一步历史。若先松开左键，本笔立即提交，继续按住右键／中键仍可调整视角。

三维套索按 B 或点击侧栏「套索」，始终留在三维。先调整载体的三轴姿态，再按住左键在该姿态平面画轮廓；鼠标松开后闭合成多边形预览。拖动沿局部法线的拉伸手柄，或输入「深度」、按 [／]，调整正向或负向拉伸；按 Enter／「放置」提交带端面和侧面的实体。「重画轮廓」重新起稿。套索轮廓与拉伸预览在放置前不修改已有工程；矩形、椭圆、菱形也支持有符号局部拉伸。

轮廓闭合后或调整拉伸深度后，可直接点击左侧「识别」，选择「中文说明」或「数学公式」；也可用「选择」点中已有组件或关系说明再识别。预览截取当前三维视角中区域内的真实像素，保留遮挡关系，并隐藏四角激光、网格、预览与选择手柄。圈内没有可识别内容时明确提示，不发送识别请求。取消或识别失败后，轮廓、深度、三轴姿态和原内容继续保留，可接着调整或放置。

三维识别候选须校对确认，结果按载体或所选内容的实际三维姿态新增为文字或公式图形；所有原元素、笔迹与公式像素保持原样，轮廓和拉伸草稿仍可继续编辑。三维识别不执行二维套索的圈内替换。内容、姿态、视角或选定版本变化后，旧候选不能直接提交；状态未变时重开可恢复上次未确认的结果。

「更多」收起高度、降低／升高、网格、间距和「关系布局」，网格默认关闭。高度输入设定笔尖高度；未调整拉伸深度时，[／] 或「降低／升高」每次改高度 60。图元缺少 `z` 时保持零层，打开视图、增删关联或移动载体不会自动重排。「关系布局」根据已记录的联系、父子和模块结构安排 X／Y／Z，循环与双向关系也能展开成立体结构；通过三维线段近交叉、穿过组件与多个投影的评分，尽量减少交叉和遮挡。分区按原姿态包围成员投影，无关联手绘保持原位。先预览，应用后才记一步历史，可取消、撤销或重做；密集联系不保证任何视角都零交叉。三维局部橡皮可处理全部内容，实体按局部体积擦除；擦痕进入实际 GPU 显示、选择和识别，并与二维共用数据。

三维数字键选工具：1 选择、2 自由笔迹、3 矩形、4 椭圆、5 菱形、6 多边形、7 箭头、8 文字、9 橡皮、0 分区，B 为三维套索。V／P／R／O／T／F、L 直线、M 公式仍可使用，Alt+A／Alt+D／Alt+E／Alt+Q 选择箭头／菱形／橡皮／多边形，G 切网格。Esc 先取消在途绘制、变换、导航或预览，无在途操作时返回二维。Ctrl+Z 撤销、Ctrl+Shift+Z／Ctrl+Y 重做、Ctrl+D 复制、Delete 删除；「保存修改」与 Ctrl+S 走相同的项目版本保存。

原生入口 `python3 native/app.py --project /工程/anatomy-名称` 与旧命令 `native/anatomy3d.py` 现在启动或复用插件服务并打开系统浏览器。Python 入口不再用软件渲染器编辑并直接覆盖 `body.json`；修改通过网页的项目版本流程保存。运行要求、无桌面模式和服务生命周期见 [桌面启动入口](../native/README.md)。

## 公式库与手写识别

左侧「公式库」提供分式、根式、上下标、分段函数、方程组、求和、积分、矩阵、概率、集合逻辑和常见工程关系。选择图形后点击「复制图形」或「确认放入画板」，直接生成独立的图片图元，保留其他文字、公式和程序映射。人读界面没有排版源码编辑框，也无需选择追加或覆盖某条表达。

公式图形由随包内嵌的 **MathJax SVG 3.2.2** 排版，再转换为本地 PNG。生成的独立 HTML 可离线选择常用模板、绘图、局部擦除和补画；旧数学数据与预览仍使用内嵌 KaTeX 的 MathML 排版。原数学表达、原始 PNG、当前 PNG 和编辑记录一起保存，公式图形不额外显示图注。

二维「套索」或 Q 像画笔一样按住拖动，松手自动闭合，不再逐点点击或按回车拼圈。进入套索会隐藏旧选择和控制手柄，鼠标经过、单击或双击图元不会打开组件编辑。完成后仍处于套索模式，可直接再圈；需要移动、缩放或编辑图元时，按 V 或点击「选择」。三维 B 套索的轮廓拉伸与当前视角识别见上节。

二维正在按住拖圈时，滚轮和除 Esc 外的快捷键暂停，避免圈选中途缩放或修改工程。按 Esc、拖动取消或失去指针捕获会取消当前圈，继续保留套索模式；工程内容和撤销历史不变。圈线随拖动更新自身，不重排已有图元。

二维圈中笔迹、公式图形、普通文字、排版公式或导入图片后，点击左侧「识别」，选择「中文说明」或「数学公式」，准备好圈内预览后自动开始识别。套索操作条仍提供「识别中文」和「识别公式」预览入口。完成的圈选始终可以打开类型选择；圈内为空时窗口明确提示，保留圈线而不发出识别请求。识别只处理圈内可见内容；确认结果时在原位置生成自然语言或公式图形。普通文字、排版公式与导入图片保持原样并新增结果；自由笔迹与公式图形继续只替换圈内部分，圈外笔迹与图形像素保留。原稿和各来源的程序映射仍可追溯。

不需要识别时，画笔本身就是可保存的内容；识别预览也可选择保留原笔迹。数学识别结果确认后生成独立公式图形，保留原始笔迹和识别来源。未识别笔迹只保存真实几何与已有说明，不声称 AI 已理解其数学内容，也不补造公式。

擦除或补画后的公式图形标为待校对，旧表达不能冒充当前表达。AI 读取当前 PNG，结合用户意图核对后才能按校对后的数学表达严格实施；校对指纹绑定当前 PNG，图片变化使先前校对失效。这一步确认人的图形意图，仍不代表业务实现已通过测试。

用鼠标、触控笔或触摸直接写在大画板上。二维没有圈选时，点击左侧「识别」先进入套索；圈选完成后再次点击「识别」选择类型，选定后自动识别，无需再点「识别笔迹」。三维没有轮廓或选中内容时会提示先画轮廓或选择组件，保持当前工具与姿态。取消类型选择会保留圈选与原稿。中文结果可用自然语言校对，数学结果以公式图形预览，识别不符时回画板调整笔迹并重新识别。中文建议每次写一行，数学一次写一条完整公式。连接状态自动更新，也可点击「重新连接」。未确认识别草稿在当前浏览器暂存，重开相同区域且状态未变时可恢复；确认后才将结果写入画板并进入撤销与项目保存，二维与三维分别按上述规则保留来源。

识别面板可选择「智能体」或「本地识别服务」。智能体模式通过 `anatomy_recognition` 将圈选 PNG 交给 DSH 或 Codex，并将候选回传网页；未配置独立执行器时显示等待接管，需要在宿主会话要求接管，网页不会自行唤醒空闲会话。可配置已登录的 Codex CLI 自动执行，或使用明确配置的 DSH 命令适配器，见 [接入说明](../docs/RELEASE-0.17.0.md)。智能体模式会按宿主配置处理图片，包括其模型服务。

本地模式分别使用 [PP-OCRv5 中文识别](https://www.paddleocr.ai/v3.0.0/en/version3.x/algorithm/PP-OCRv5/PP-OCRv5.html) 与 [PP-FormulaNet 公式识别](https://www.paddleocr.ai/v3.1.1/en/version3.x/module_usage/formula_recognition.html)。在网页填入本机服务地址并点击「连接」，可连接另一端口的本地服务，也可从独立 HTML 手动连接；项目版本保存仍由原画板服务负责。识别是候选结果，复杂笔迹、上下标和汉字仍需校对。

调用 `anatomy_render` 时默认自动启动或复用本地服务，并请求系统浏览器打开返回的 `url`。网页先打开，中文与公式模型在后台准备，手写面板显示实际加载状态。同一画板重复生成复用同一服务；默认端口 8767 被其他页面占用时自动选择空闲端口，不会关闭已有服务。自定义输出文件名也支持。

识别服务程序、安装器和固定依赖清单随插件发布与更新；Python、识别依赖和模型权重需要在每台电脑准备。已有 Python 3.8+ 时，在插件目录执行：

```bash
npm run recognition:install
npm run recognition:warmup
```

安装器建立用户缓存里的独立 Python 环境，不修改全局 Python；渲染时自动使用它，也可显式配置 `pythonPath`。`npm run recognition:check` 检查环境与依赖版本，更新插件后执行 `npm run recognition:update`；依赖清单没有变化时复用环境，模型缓存持续保留。`-- --python /路径/python` 可指定已有 Python。首次模型准备下载公开权重，换电脑需要重新安装依赖并下载，不能跨操作系统复制虚拟环境。未安装 Python 或当前系统没有兼容的 Paddle wheel 时会报告具体错误，插件不捆绑所有平台的 Python 与模型。

- `anatomy_render({ body: 'project', open: false })`：启动服务，只返回地址。
- `anatomy_render({ body: 'project', serve: false })`：只生成 HTML。
- 插件配置 `autoServe: false` / `autoOpen: false` 可更改默认行为；单次工具参数优先。
- 返回的 `service.status` 区分 `starting`、`ready`、`unavailable`、`disabled`，`browser.status: requested` 仅表示已发出打开请求。无法自动打开时使用返回的 `url`。

直接双击独立 HTML 或使用普通静态服务器时，绘图与公式可用，但浏览器不能自行启动 Python。需要手动启动时，从插件目录运行 `npm run serve -- --dir anatomy-freeboard --port 8767 --warmup`，或用 `--file /路径/自定义画板.html` 指定文件，再打开服务打印的地址。

服务只监听本机回环地址，仅提供指定画板、项目版本和识别接口；不会开放整个工程目录。手动连接使用绑定网页来源的短期 token，跨来源只开放本地识别接口。智能体交接图片与请求保存在画板目录的 `.anatomy-runtime/recognition/requests/`，用于宿主读取和回传；请求 10 分钟后过期，关闭或改稿会取消，历史请求文件保留供核对，勿提交版本库。服务独立于生成命令运行，关闭网页不会停止它。更新后生成画板会核验代码版本，安全重启归属当前画板的旧服务；无法核验身份时报告原因。要停止服务，可核实返回的 `service.pid` 对应本画板后结束该进程。

`npm run test:ocr` 测试服务输入校验、中文/公式分流、模型结果解析和本地访问边界；`python3 test/recognition-smoke.py http://127.0.0.1:8767` 可用合成笔迹检查实际模型对“中文”和带上标公式的识别通路；它不代表复杂手写的准确率。

## 插入图片

左侧靠上的「图片」选择本地 PNG、JPEG 或 WebP，也可粘贴剪贴板图片或直接拖入画板。二维选择、粘贴默认放到空白处并避让已有内容，拖入按落点放置；三维先挂在笔尖载体预览，移动、旋转后按 Enter 或「放置」提交。图片可移动、缩放和旋转；双击图注在原位置写自然语言说明，并可关联该图片部位的程序映射与源码依据。

单张图片最多 6 MiB，整张画板当前图片与公式原图合计最多 8 MiB；相同内嵌数据去重计入。图片直接嵌入本地画板 JSON，和图注一起进入项目保存与历史，不需要另外上传图片或维护原文件路径。AI 读取选定版本时可以直接看到图片，同时获得尺寸、内容指纹和完整图片数据，用于对照与严格核对。

插入图片不自动证明其含义或建立源码关联。AI 应结合图注、数学关系与实际工程复核，不凭图片编造实现。

## AI 接入

```javascript
anatomy_init({ repo: '/工程目录', body: 'project', title: '订单处理', oneline: '把提交的订单转为可交付的结果。' })
anatomy_board({ body: 'project', board: {
  version: 1,
  elements: [{
    id: 'accept-order', type: 'rect', x: 80, y: 120, width: 280, height: 160,
    text: '接收订单并检查交付条件', math: '可接受数量 ≥ 1',
    fill: '#eff6ff', stroke: '#6366f1',
    implementation: { language: 'JavaScript', code: 'validateOrder(order)', note: '填写经过阅读确认的实际实现。' },
    anchors: [{ file: 'src/order.js', symbol: 'validateOrder', role: 'implementation', reason: '检查订单的接受条件' }]
  }]
} })
anatomy_render({ body: 'project' })
anatomy_board({ body: 'project', element: 'accept-order' }) // 读取所点部位的程序映射
```

示例中的文件与符号必须替换为工程实际存在的对象。`anatomy_board` 保存整张画板，先读当前值再修改，保留其他图元、源码基线与扩展字段。浏览器修改包用 `baseHash` 检查是否过期；不能改哈希或强制覆盖来消除意图冲突。

画板在 `body.json.board`。每个图元具有稳定 `id`、`type`、位置与宽高；笔迹与多边形用 `points` 表示按宽高缩放的相对坐标。直线和箭头可用 `from`、`to` 关联图元。`targets` 可关联既有 `organ` / `flow`，但自由画板无需它们。线条连接代表作者绘制的关系，不会自动变成程序调用或数据依赖。

局部擦除使用 `erasures: [{surface: "body" | "label", points: [[u,v], ...], radius: [ru,rv]}]`。点和半径均为图元载体中的归一化局部坐标；三维局部体积使用三坐标点和三半径。图元原文、原图、`id` 和程序映射保持，显示、命中、范围选择及识别共同读取擦痕。连线按起点方向映射，关系说明用独立载体；擦痕不能保存成挡住下面内容的白色对象。单个部位最多保存 8192 个擦除点。

MCP 返回图片时会合成实际擦痕，并以当前可见 PNG 的数据生成公式校对指纹。擦过的 JPEG／WebP 或暂不支持的 PNG 编码不会被冒充成未擦原图，完整来源与擦痕仍保留在工程数据中。

可选 `z` 记录层高，缺省为 0；空间笔迹的 `points3d` 保留逐点高度。`points` 与 `points3d` 长度匹配时，当前图元位置、尺寸及相对点决定 x／y，对应三维点决定 z，二维移动、缩放或复制后仍保留空间轨迹。读取和保存时保留这两种表示及扩展字段。

空间姿态以度数保存：可选 `rotationX`、`rotationY` 绕 X／Y 轴，旧字段 `rotation` 继续表示 Z 轴角度，缺省均为 0。姿态围绕图元中心 `(x + width / 2, y + height / 2, z)`，按 `Rz * Ry * Rx` 应用。可选 `extrusion` 是沿图元局部 Z／法线的有符号深度，支持 `polygon`、`rect`、`ellipse`、`diamond`；负数向相反方向拉伸，0 保持平面。新增角度与拉伸深度须为 ±10000000 范围内的有限数。程序映射的 `geometry`、项目版本和二维编辑保留这些字段；不把三维姿态转换成另一份工程数据。

旧图元的 `math` 保存主表达，`mathExpressions` 保存带稳定标识的附加表达；旧画板无需批量迁移即可继续读取，修改无关内容时保留全部表达及笔迹。新公式图形使用独立 `type: "image"`，`math` 为空，排版源码只进入 `formulaGraphic`。

图片图元使用 `type: "image"`，`image` 保存 `src`（内嵌 data URL）、`alt`（自然语言说明）和文件原始 `width`、`height`。图注编辑同步 `text` 与 `image.alt`；画面缩放只改变图元的宽高，不修改图片原始尺寸。MCP 返回标准图片内容供 AI 看图，简短文字包含尺寸与 SHA-256；完整图片 JSON 留在结构化结果中供严格核对。项目保存请求上限为 12 MiB。

## 修改与校验

AI 开工先调用 `anatomy_selected_version({ dir })`（有当前页面地址时用 `{ url }`），读取页面选定完整版本和当前图片，用返回的 `selectionRevision` 应用。尚未采用项目保存的旧页面才检查 `anatomy_pending_edits`。自然语言和数学表达是人的意图，程序映射和源码关联是下层落实依据。改完实际实现后运行相关测试，核对意图、数学关系和边界，再用 `reviewSources: true` 更新所复核图元的源码基线。

公式图形的机读数据包含 `originalMath`、`originalImage`、`currentMath`、`semanticStatus`、排版来源和 `edits`。初始图形为 `source-aligned`；擦除、补画后 `currentMath: null` 且 `semanticStatus: "needs-review"`。这些待校对草稿仍可保存、读取和普通渲染；严格应用与 `requireVerified: true` 的交付会拒绝按未经校对的原公式实施。

读取返回的 `formulaSemantics` 给出每张当前 PNG 的 `visualHash`。AI 必须先查看图片、结合用户意图核对，再明确提交本次校对：

```javascript
anatomy_selected_version({
  dir: '/工程目录/anatomy-project',
  apply: true,
  selectionRevision: '本次读取返回的选择修订',
  formulaReviews: [{
    element: '需要校对的公式图元标识',
    currentMath: '依据当前图片与用户意图核对的数学表达',
    visualHash: '本次读取返回的当前PNG的SHA-256'
  }]
})
```

所有待校对图形均需覆盖；指纹不符、选择修订或工程基线变化时拒绝。工具另存不可变的校对新版后严格应用，不修改原历史；返回 `formulaReview` 标明来源版本与新版。`reviewed` 的 `review.visualHash` 绑定当前 PNG 数据，后续图片变化必须重新校对。图形校对、源码指纹和业务测试是独立证据，不能相互代替。

写入检查图元结构、有限几何值、唯一标识、有效端点与工程引用，并检查源码文件、符号和内容变化。程序语言进入人读说明会被拒绝；自动识别基于语法线索，不能代替作者复核。普通写入保留原源码基线，不能用重新保存来掩盖源码变化。

保存了意图不等于完成了实现。任意自然语言、自由图形、原笔迹和数学表达不会被自动证明，也不会自动变成运行依赖。程序映射关联上层语义与下层实现，仍须 AI 结合源码复核。已有结构模型的 `rules` 与 `anatomy_verify` 继续支持绑定版本的数值证据检查；没有实测证据时不能声称实现满足要求。

## 工具与文件

自由画板主要使用 `anatomy_init`、`anatomy_board`、`anatomy_render`、`anatomy_check`、`anatomy_show`、`anatomy_map`、`anatomy_digest`。工程协作用 `anatomy_selected_version`、`anatomy_mapping`、`anatomy_impact`、`anatomy_apply_edits`、`anatomy_pending_edits`、`anatomy_history`、`anatomy_revert`。

既有结构模型继续支持 `anatomy_scaffold`、`anatomy_organ_put`、`anatomy_flow_put`、`anatomy_remove`、`anatomy_brief`、`anatomy_scenario_put`、`anatomy_policy`、`anatomy_activate`、`anatomy_verify`。旧工程首次渲染时自动转换为可自由排布的图元，保留原工程对象的关联；保存画板后沿用作者布局。

工程目录保存 `body.json`、可选的 `organs/` 与 `flows.json`、`anatomy.html`、`receipt.json`、`MAP.md`、`DIGEST.md`、`edits/` 和历史记录。画板数据应随工程一起管理。

## 安装

插件目录与本仓库同级放置即可（DSH bundle 层）：

```yaml
# cordis.patch.yml 已随包提供
- insert:
    - id: dsh-anatomy
      name: '@dsh-external/dsh-anatomy'
      config: { rootDir: ., lang: zh }
```

在 DSH profile 里加一条依赖并把它放进 bundles：

```json
{
  "dependencies": { "@dsh-external/dsh-anatomy": "link:/path/to/dsh-anatomy" },
  "dsh": { "profile": { "bundles": ["@dsh-external/dsh-anatomy"] } }
}
```

配置项：`rootDir`（解剖体存放根目录，默认 `.`）、`lang`（`zh` | `en`，默认 `zh`）、`digestFile`（默认 `DIGEST.md`）。

## 开发与参考

`npm test` 运行工具端到端、映射与验证、画板数据和交互事件回归；`npm run test:ocr` 检查识别服务边界，`python3 native/selftest.py` 检查桌面启动器。GPU 场景的浏览器验证独立运行，需要先准备可选的 Playwright 与 Chromium：

```bash
npm install --no-save --package-lock=false playwright
npx playwright install chromium
npm run test:space:browser
```

发布包已包含离线 Three.js 运行时，普通使用不需要安装构建工具。维护该运行时时，使用固定依赖重新打包；也可把已有 `node_modules` 目录作为参数传入：

```bash
npm install --no-save --package-lock=false three@0.186.1 esbuild@0.28.2
npm run build:space
# 或 node scripts/build-space.mjs /路径/node_modules
```

浏览器测试覆盖实际 WebGL 场景及输入路径；事件 stub 测试只替换浏览器边界，两者不能替代真实显卡和复杂工程的使用验证。

从本地服务重新打开旧版生成页面时，服务使用当前插件的界面在内存中呈现，不改磁盘 HTML、画板或保存历史。打开中的页面发现新版服务会提示更新；先完成有效保存再刷新，等待期间的新编辑继续保留。独立 HTML 仍须重新生成。
